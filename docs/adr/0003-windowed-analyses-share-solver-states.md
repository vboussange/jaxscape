# Windowed analyses share solver states

Windowed analyses keep, within a process, the latest solver state of each distance, graph shape and dtype, in a registry of `windowed_analysis.py` keyed by `(distance.exact(), shape, dtype)`, so that randomized distances share the states of the exact distances that they estimate. An analysis builds a state, on a graph of uniform permeability, only for a key without one, and each run, calibration of the block correction and default-proximity profile starts from the latest state and registers the state it leaves. Queries reinitialize the state they receive, so that, up to rounding, results do not depend on the state that a run starts from. Before, every analysis object and every repeated `run()` paid a cuDSS analysis, because a refactorization uses up the cuDSS handle of its input: on the 894 x 925 tile of the Maryland land cover, creating a resistance analysis took 4.6 s, and a Spielman connectivity 5.2 s. With shared states, they take 0.01 s, except for the first analysis of a process, and 1.35 s. Distances that cannot be hashed, such as those with an `AMJaxCGSolver`, keep the state of each analysis, and analyses created or run while JAX traces them neither read nor register states: the tracers of a traced computation are invalid outside it.

The registry holds the states of the 8 most recently used keys, as many as spineax keeps cuDSS factorizations by default, and releases them at the exit of the interpreter, before the modules of native objects such as CHOLMOD factorizations shut down. The notebook's resistance analyses hold two: a tile and a window. On the Maryland tile in float32, a `GridMultigridSolver` state holds 52 MiB of JAX arrays: the stencil slots of the stored entries, 16 MiB, the stencils and interpolations of the hierarchy, and the factor of the coarsest grid. A `CuDSSSolver` state holds 132 MiB of JAX arrays, the CSR pattern and values of the matrix, and the cuDSS factorization outside JAX's memory pool: the device memory of the process grew by 706 MiB while building it on an RTX 3090, against 270 MiB for the multigrid state.

A public `state=` argument of the analyses would share states explicitly, at the cost of new API surface, and callers would still have to thread the state that each run leaves, because cuDSS handles are used up. A cache inside `CuDSSSolver` sees the states that it builds, but only the engine knows the state that a run leaves after refactorizing tile after tile, which the next run must start from.
