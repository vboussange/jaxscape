    Distances¤

    A distance object (AbstractDistance) takes a graph and returns the distances between some of its vertices. LCPDistance, ResistanceDistance and FreeEnergyDistance compute them from the edge weights, which they read as conductances; EuclideanDistance computes them from the pixel coordinates of a GridGraph. Every distance is called in the same way: distance(graph, nodes=nodes) for the distances among nodes, distance(graph, sources=sources, targets=targets) for the distances from sources to targets, and distance(graph) for the distances between all pairs of vertices. ResistanceDistance and FreeEnergyDistance solve linear systems, with a solver chosen as Linear solvers describes.

    Interface¤

    AbstractDistance defines the queries of every distance. AbstractSolverDistance adds the solver state of the distances that solve linear systems.

    jaxscape.distance.AbstractDistance ¤

    Abstract base class for distance computations on graphs.

    A distance is called on a graph, with vertices given as vertex indices or, on a GridGraph, as pixel coordinates.

    Arguments:

    • graph: Graph on which to compute distances.
    • sources: Source vertices, as vertex indices with shape (m,) or, for a GridGraph, pixel coordinates with shape (m, 2).
    • targets: Target vertices, as vertex indices with shape (k,) or, for a GridGraph, pixel coordinates with shape (k, 2).
    • nodes: Vertices of the pairwise distances, as vertex indices with shape (k,) or, for a GridGraph, pixel coordinates with shape (k, 2).
    • state: Optional solver state. Defaults to automatic initialization.

    Specify either: nodes alone, sources and/or targets, or neither (for all-pairs).

    Attributes:

    • sources_share_work: Whether a query from several sources costs much less than one query per source, as when the linear systems that a query solves serve every source with one solver state, such as a factorization or a multigrid hierarchy. Windowed analyses then compute the distances of many sources on the graph of one tile. Defaults to False.
    • symmetric: Whether the distance from i to j equals the distance from j to i on graphs whose adjacency matrix is symmetric, as those of windowed analyses are. With coarsening, SensitivityAnalysis then computes the sensitivity of the quality-weighted connectivity to quality without differentiation. Defaults to False.
    • averages_sources: Whether window queries take source_weights and return the mean of the distances from the pixels around each source, with these weights, at the cost of one query (see sources_to_windows_distance). With coarsening, SensitivityAnalysis then computes the sensitivity of connectivity to the permeability of a block centre from the distances of its block source, the pixels that the block centre stands for. Defaults to False.

    Returns:

    Distance array with shape depending on the inputs.

    Example

    from jaxscape import LCPDistance, GridGraph
import jax.numpy as jnp

distance = LCPDistance()
permeability = jnp.ones((12, 12))
grid = GridGraph(permeability, fun=lambda x, y: (x + y) / 2)

# All-pairs distance
D = distance(grid)  # Shape: (n_nodes, n_nodes)

# Using vertex indices
D = distance(
    grid,
    sources=jnp.array([0, 1]),
    targets=jnp.array([10, 20]),
)

# Using coordinates (for GridGraph)
D = distance(
    grid,
    sources=jnp.array([[0, 0], [1, 1]]),
    targets=jnp.array([[10, 10]]),
)

# Pairwise among subset
D = distance(grid, nodes=jnp.array([0, 5, 10]))  # Shape: (3, 3)

    reinit(graph: AbstractGraph, state: typing.Any) -> typing.Any ¤

    Return the state for graph, reusing what the solver can from state.

    Queries on graph take the returned state, and so does the next reinit. Carry the returned state into the next queries and reinit, whatever the distance and solver. The state is None for a distance without a solver, such as one with solver=None. With Lineax's and JAXScape's solvers, it is never None. For a solver that keeps nothing from one matrix to the next, such as lineax.CG, reinit ignores state and returns init(graph).

    Arguments:

    • graph: Graph of the next queries.
    • state: State from init or an earlier reinit.

    Returns:

    State for graph, without gradient.

    sources_to_windows_distance(graph: GridGraph, sources: Array, size: int, state: typing.Any = None, source_weights: jax.Array | None = None) -> Array ¤

    Return the distances from each source to the pixels of its window.

    The window of a source is the square of size pixels a side centred on it, and it must lie inside the grid: the query raises otherwise. Windowed analyses query the distances of their block centres through this method, and the profile of their default proximity through a sources-to-targets query. By default, it computes the distances from the sources to every vertex and slices their windows: it holds m * n distances for m sources and n vertices, besides the memory of the query. A distance may override it to hold fewer values, as ResistanceDistance does, or for speed, as LCPDistance does on grid graphs.

    Arguments:

    • graph: Grid graph on which to compute distances.
    • sources: Source vertex indices with shape (m,).
    • size: Odd number of pixels along a side of the windows.
    • state: Optional solver state. Defaults to automatic initialization.
    • source_weights: Optional weights of the pixels around each source, for distances that average sources (see averages_sources); other distances raise. Defaults to the source alone.

    Returns:

    Distances with shape (m, size, size). For source i at row r and column c, entry [i, a, b] is the distance to the pixel at row r - size // 2 + a and column c - size // 2 + b.

    jaxscape.distance.AbstractSolverDistance ¤

    Distance whose queries solve linear systems in one sparse matrix per graph.

    That matrix is the system matrix of the graph: sparse, symmetric and positive definite, such as the grounded Laplacian of ResistanceDistance. Subclass it with solver and system_matrix to get the solver state lifecycle of init and reinit.

    Attributes:

    • solver: Lineax solver of linear systems in the system matrix, or None for dense linear algebra.

    system_matrix(graph: AbstractGraph) -> BCOO ¤

    Return the system matrix of graph.

    Arguments:

    • graph: Graph of the queries.

    Returns:

    The system matrix, as a BCOO matrix.

    init(graph: AbstractGraph) -> typing.Any ¤

    Build the solver state for graph.

    JAXScape's sparse solvers, except CholmodSolver, read concrete sparse indices, and AMJaxCGSolver builds its preconditioner on the host, so call it outside jax.jit. ResistanceDistance also builds the state of a GridGraph inside jax.jit.

    init returns the state that solver.init builds for the system matrix: a state for Lineax's and JAXScape's solvers, and None only with solver=None. Carry the state through reinit and the queries whatever the solver. For a solver that keeps nothing from one matrix to the next, such as lineax.CG, reinit ignores state and returns init(graph).

    Arguments:

    • graph: Graph whose system matrix the state is built for.

    Returns:

    State to pass to queries and to reinit, or None without a solver.

    Implemented distances¤

    Euclidean distance¤

    The straight-line distance between pixels, in pixels. It does not depend on the edge weights.

    jaxscape.euclidean_distance.EuclideanDistance ¤

    Straight-line distance between pixels, in pixels. It requires a GridGraph. Distances take the floating dtype of the grid, or JAX's default floating dtype for an integer or boolean grid.

    Example

    from jaxscape import EuclideanDistance

distance = EuclideanDistance()
dist = distance(grid, sources=source_coords, targets=target_coords)

    Least-cost path distance¤

    The smallest sum of the edge costs 1 / a along a path between two vertices, for the conductance a of each edge.

    jaxscape.lcp_distance.LCPDistance ¤

    Compute least-cost path distances with edge cost 1/a for conductance a, using algorithm.

    For V vertices, E stored edges and S requested sources:

    • Bellman–Ford (default): Relaxes sparse edges until distances stop changing. Each round costs O(S(V + E)), and it takes one round more than the most edges on a shortest path, at most V − 1. Favor it for sparse graphs or a small number of sources. Window queries on a GridGraph relax the grid by shifting rasters (see sources_to_windows_distance).
    • Floyd–Warshall: Computes a dense all-pairs distance matrix by considering each vertex as an intermediate stop. Costs O(V³) time, even when requesting only selected pairs. Favor it for small dense graphs when most or all pairs are needed.

    For a unique shortest path, the derivative of its distance with respect to a is -1/a**2 on that path and zero elsewhere: increasing conductance decreases the distance. At exact ties, Bellman–Ford chooses a generalized gradient by splitting sensitivity equally among optimal incoming edges at each vertex; complete paths need not receive equal weight. Raster gradients follow by the chain rule through GridGraph.fun.

    Attributes:

    • algorithm: "bellman-ford" (default) or "floyd-warshall".

    Note

    Bellman–Ford requires positive, finite conductances; zero means no edge. Gradients assume that the edges of the graph stay the same. jax.jvp, jax.jacfwd, and higher-order derivatives are currently unsupported.

    Example

    from jaxscape import LCPDistance, GridGraph
import jax.numpy as jnp

grid = GridGraph(jnp.ones((5, 5)), fun=lambda x, y: (x + y) / 2)
distance = LCPDistance()
D = distance(grid, sources=jnp.array([0, 1]), targets=jnp.array([10, 20]))
    sources_to_windows_distance(graph: GridGraph, sources: Array, size: int, state: typing.Any = None, source_weights: jax.Array | None = None) -> Array ¤

    Return the distances from each source to the pixels of its window.

    As AbstractDistance.sources_to_windows_distance. With Bellman–Ford, a relaxation round shifts the distance rasters of all sources by each neighbour offset of graph, adds the edge costs and takes elementwise minima: a few fused operations, without the gathers and scatters of sparse edges, which are slow on GPUs. With four neighbours, one expression runs two rounds. The adjoint propagation of the gradient shifts rasters the same way. The distances are those of the sparse edges, exactly, and the gradients the same to rounding. Windowed analyses run faster this way than with sparse edges, on GPUs and on CPUs.

    Rounds cannot be fewer: each distance is the sum of the edge costs of a shortest path, rounded after each edge, which the backward pass relies on to find the edges of shortest paths. Sweeps along rows and columns as prefix scans would add costs in another order.

    The query needs concrete graph.neighbors; when they are traced, as for a graph passed into jax.jit, it relaxes the sparse edges.

    Arguments:

    • graph: Grid graph on which to compute distances.
    • sources: Source vertex indices with shape (m,).
    • size: Odd number of pixels along a side of the windows.
    • state: Ignored.
    • source_weights: Raises if given: least-cost path distances do not average sources.

    Returns:

    Distances with shape (m, size, size).

    Resistance distance¤

    The effective resistance between two vertices when each edge is a resistor of conductance a. Its method is ExactResistance, which computes it exactly, or SpielmanApproximation, which estimates it from random projections.

    jaxscape.resistance_distance.ResistanceDistance ¤

    Resistance distance: the effective resistance between two vertices of a graph whose edge weights are conductances.

    Queries compute it by solving linear systems in the Laplacian of the graph grounded at one vertex, or from the pseudo-inverse of the Laplacian.

    Attributes:

    • solver: Lineax solver of linear systems in the grounded Laplacian, for BCOO sparse matrices, or None for dense linear algebra. Defaults to jaxscape.solvers.GeometricMultigridCGSolver(), conjugate gradients with a geometric multigrid preconditioner, which solves the grounded Laplacians of grid graphs, such as those of a GridGraph, on any device without an optional dependency, also in float32 and inside jax.jit. With the default, queries on other graphs raise an error: pass jaxscape.solvers.CholmodSolver, AMJaxCGSolver or CuDSSSolver, or solver=None. Choosing a solver gives the solver for each device and query. Without a solver, exact all-pairs and nodes-to-nodes queries compute the pseudo-inverse of the dense Laplacian, and other queries a dense Cholesky factorization of the grounded Laplacian: their memory grows with the square of the number of vertices, which suits small graphs. Windowed analyses with exact resistances, which solve a linear system for every vertex of a tile, can run faster on a CPU without a solver. In float32, the pseudo-inverse loses accuracy when conductances span orders of magnitude.
    • method: A resistance distance method. Defaults to ExactResistance(). Use SpielmanApproximation(epsilon=..., seed=...) for the randomized Spielman-Srivastava approximation.

    Example

    import jax.numpy as jnp
from jaxscape import GridGraph, ResistanceDistance, SpielmanApproximation
from jaxscape.solvers import AMJaxCGSolver, CholmodSolver

permeability = jnp.ones((3, 3))
grid = GridGraph(permeability, fun=lambda x, y: (x + y) / 2)

# Default: GeometricMultigridCGSolver, for grid graphs
distance = ResistanceDistance()
dist = distance(grid)

# Dense solves, for small graphs of any kind
distance = ResistanceDistance(solver=None)

# A sparse direct solver, for other graphs
distance = ResistanceDistance(solver=CholmodSolver())

# With an initialized AMG-preconditioned CG solver
distance = ResistanceDistance(solver=AMJaxCGSolver(rtol=1e-6))
state = distance.init(grid)

dist = distance(grid, state=state)

# Carry a state from one graph to the next, as an optimization loop does.
# AMJax keeps its hierarchy.
updated_permeability = permeability * 1.1
updated_grid = GridGraph(updated_permeability, fun=lambda x, y: (x + y) / 2)
state = distance.reinit(updated_grid, state)
dist = distance(updated_grid, state=state)

# Approximate resistance distance, with the default solver
distance = ResistanceDistance(method=SpielmanApproximation(epsilon=0.05))

dist = distance(grid)

    Grounding, float32 and memory

    Except dense all-pairs and nodes-to-nodes queries, which compute the pseudo-inverse, queries solve linear systems in the Laplacian grounded at one vertex: among the vertices whose weighted degree is at least half the largest, the nearest to the middle vertex. On a grid graph of h rows and w columns, with rook or queen contiguity, the middle vertex is its centre pixel, of row h // 2 and column w // 2. The ground of a window or a tile of a windowed analysis is thus a pixel of high permeability at or near its centre, where its sources lie, which keeps float32 distances free of cancellation. A ground on a barrier would make the float32 system too ill-conditioned to solve.

    On large tiles, the float32 solutions of sparse direct solvers are inaccurate around the ground vertex. For the sensitivity of connectivity to permeability on large tiles, use GeometricMultigridCGSolver, the default, in float32, or a direct solver in float64.

    Exact sources-to-targets queries on n vertices, from m sources to k targets, hold the potentials of all targets when they are a few million values, as in small windows. Beyond, they solve the targets in chunks of c, about a thousand, and hold at most n * (m + c) potentials. Computing their gradient solves the system of each target once more.

    Warning

    The graph must be undirected for resistance distance to be well-defined. With a solver, it must also be connected: the grounded Laplacian of a disconnected graph is singular, and queries raise an error. GeometricMultigridCGSolver then reports a non-finite solution, or a solve that did not converge within max_steps. A grid graph is disconnected when edges of zero conductance cut it, as fun gives between pixels of zero permeability. Windowed analyses raise permeability to a floor, so that their graphs are connected. Without a solver, the pseudo-inverse gives the resistances within each connected component, and finite values between components, and sources-to-targets queries give NaN.

    sources_to_windows_distance(graph: GridGraph, sources: Array, size: int, state: typing.Any = None, source_weights: jax.Array | None = None) -> Array ¤

    Return the distances from each source to the pixels of its window.

    As AbstractDistance.sources_to_windows_distance. With source_weights \(u\) of a source, its distance to pixel \(j\) is the mean of the resistances \(R_{ij}\) from the pixels \(i\) around it, with the weights \(u_i\):

    \[\sum_i u_i R_{ij} = R_{uj} + \sum_i u_i R_{ui}, \qquad R_{uj} = (u - e_j)^T L^+ (u - e_j),\]

    where \(L^+\) is the pseudo-inverse of the Laplacian, and \(R_{uj}\) the resistance between pixel \(j\) and the pixels of \(u\), which a unit current enters with the weights \(u\). The query computes \(R_{uj}\) for the pixels of the window, and adds the within-block mean resistance \(\sum_i u_i R_{ui}\), which is 0 for a source alone. Exact queries solve for the vector \(u\) in place of the source, and for every pixel of the graph.

    With SpielmanApproximation, the query solves the k projections projection_batch_size at a time, and adds the squared differences of their potentials between each source, the mean of its pixels with the weights \(u\), and the pixels of its window. It holds the potentials of one batch of projections and the windows.

    Its gradient estimates the gradient of the exact resistances, contracted with the cotangent of the estimates, from k random probes of the pairs of a source and a pixel of its window, solved projection_batch_size at a time with two right-hand sides each. Each probe draws a sign per source and a sign per pixel, whose product weighs a pair. The estimate of each stored edge is unbiased, and varies much less between seeds than the gradient of the estimates themselves. Its noise falls as epsilon decreases.

    Arguments:

    • graph: Grid graph on which to compute distances.
    • sources: Source vertex indices with shape (m,).
    • size: Odd number of pixels along a side of the windows.
    • state: Optional solver state. Defaults to automatic initialization.
    • source_weights: Optional non-negative weights of the pixels around each source, centred on it, which sum to 1, with shape (m, side, side) for an odd side of at most size. Defaults to the source alone, side = 1.

    Returns:

    Distances with shape (m, size, size).

    debiased_proximity(proximity: collections.abc.Callable[[jax.Array], jax.Array], graph: AbstractGraph) -> collections.abc.Callable[[jax.Array], jax.Array] ¤

    Return the proximity to apply to the distances of queries on graph.

    With SpielmanApproximation, an estimate \(\hat R\) of the resistance \(R\) is unbiased, with variance \(2 R^2 / k\) for \(k\) projections. A proximity \(K\) convex in \(R\) is then biased upward, by about \(R^2 K''(R) / k\), which grows with epsilon. The returned proximity is corrected to second order:

    \[K(\hat R) - \frac{\hat R^2}{k} K''(\hat R)\]

    For a negative exponential, it is \(K(\hat R) \big(1 - (\hat R K'(\hat R) / K(\hat R))^2 / k\big)\). The correction does not reduce the variance of the proximities. It assumes the variance of one pair: the mean resistances from source weights (see sources_to_windows_distance) vary less, and the correction of a convex proximity of them is slightly too large. Exact resistances keep proximity.

    Arguments:

    • proximity: Function mapping resistances to proximities, twice differentiable.
    • graph: Graph of the queries.

    Returns:

    Function mapping the resistances of queries on graph to proximities.

    jaxscape.resistance_distance.ExactResistance ¤

    Exact resistance distances, from the pseudo-inverse of the Laplacian or from linear systems in the grounded Laplacian.

    jaxscape.resistance_distance.SpielmanApproximation ¤

    Randomized approximation of resistance distances by the random projections of Spielman and Srivastava.

    Attributes:

    • epsilon: Accuracy parameter. Smaller values use more random projections: k = ceil(log(n_vertices) / epsilon**2). All-pairs and sources-to-targets queries solve k linear systems and hold k potentials of every vertex; nodes-to-nodes queries solve one per node. Window queries, those of windowed analyses, solve k linear systems and hold the potentials of projection_batch_size of them. Their gradient solves 2 * k more, two right-hand sides for each of k random probes, projection_batch_size probes at a time.
    • seed: Random seed for the Rademacher edge projections. Each projection draws its signs from seed and its index, so that all queries on a graph share their projections, in float32 and float64, with and without 64-bit types (jax_enable_x64). The probes of the gradient of window queries draw their signs from the same seed.
    • projection_batch_size: Number of projections that window queries solve together. Other queries draw the random signs of this many projections together when the signs of all projections, one per stored edge and projection, exceed SPIELMAN_DENSE_PROJECTION_MAX_SIGN_ENTRIES entries, and all at once below. Larger batches can improve throughput at the cost of more working memory.

    Free-energy distance¤

    A distance set by the inverse temperature theta, between the least-cost path distance and the resistance distance: it approaches the least-cost path distance as theta grows, and a multiple of the resistance distance as theta tends to 0.

    jaxscape.free_energy_distance.FreeEnergyDistance ¤

    Symmetric first-hitting free-energy distance with edge costs \(1/a_{ij}\).

    Attributes:

    • theta: Finite positive scalar inverse temperature. Larger values concentrate the path distribution on least-cost paths. Distances are differentiable with respect to theta.
    • solver: Lineax solver of linear systems in the system matrix, from the same choices as for ResistanceDistance, or None, the default, for dense linear algebra, which suits small graphs. Larger graphs need a sparse direct solver, CholmodSolver on CPU and CuDSSSolver on GPU: iterative solvers, GeometricMultigridCGSolver included, need tolerances far below their defaults to resolve the small entries of \(Z\) between distant vertices. See Choosing a solver.

    For conductances \(a_{ij}\), let \(c_{ij}=1/a_{ij}\) on present edges, \(P_{ij}=a_{ij}/\sum_k a_{ik}\), and \(Z=(I-P\odot e^{-\theta C})^{-1}\). The first-hitting partition is \(z^h_{ij}=Z_{ij}/Z_{jj}\) and \(d_{ij}=-(\log z^h_{ij}+\log z^h_{ji})/(2\theta)\). For the derivation, see Kivimäki, Shimbo & Saerens and Françoisse et al..

    The graph must be connected and symmetric, with positive finite conductances on present edges. Conductance enters both the edge costs and the transition probabilities. As theta grows, the distance approaches the least-cost path distance with edge costs \(c_{ij}\). On a graph without self-loops and with m undirected edges, the small-theta limit is m times the effective resistance. Solver state depends on the conductances and on theta; pass it through reinit when either changes.

    Precision and errors: float32 and float64 inputs are supported. Entries of \(Z\) decay exponentially with path cost, and float64 resolves smaller entries, hence larger distances and larger theta. The logarithm of each queried entry is checked against an error estimate computed from the residual of the solve; entries that the precision does not resolve raise an EquinoxRuntimeError, and are never clipped or substituted. The estimate includes heuristic rounding allowances, so accuracy should be validated for the intended workload. Checks use eqx.error_if; on GPU, a failed check may be reported without raising, depending on EQX_ON_ERROR.

    Differentiation: first-order reverse-mode differentiation reuses the solutions of the forward computation. Forward-mode and higher-order derivatives are not validated.

    Example

    import jax.numpy as jnp
from jaxscape import FreeEnergyDistance, GridGraph

raster = jnp.array([[0.8, 1.2], [1.4, 0.9]])
grid = GridGraph(raster, fun=lambda x, y: (x + y) / 2)
distances = FreeEnergyDistance(theta=0.5)(grid, nodes=jnp.array([0, 3]))
