    Linear solvers¤

    ResistanceDistance and FreeEnergyDistance internally solve linear systems. The choice of solver directly affects runtime and memory usage.

    For substantial landscapes, choose an explicit sparse solver:

    • On CPU, start with CholmodSolver when a sparse factorization fits in memory; try PyAMGSolver when factorization storage is too costly.
    • On an NVIDIA GPU, use CuDSSSolver when a sparse Cholesky factorization fits in GPU memory.
    • For other JIT-compiled CPU or GPU execution, use Lineax CG, or AMJaxCGSolver when a reusable multigrid preconditioner helps convergence. AMJax setup runs on CPU.
    • The default, solver=None, uses a dense solve and is suited to small graphs only.

    Solver tolerances depend on the workload and precision. Check accuracy for your queries; solver convergence alone does not establish accurate distances.

    lineax solvers¤

    Use a Lineax solver compatible with the sparse symmetric positive-definite operator, such as Conjugate Gradient:

    import lineax as lx
from jaxscape import FreeEnergyDistance, ResistanceDistance

solver = lx.CG(rtol=1e-6, atol=1e-6)
resistance = ResistanceDistance(solver=solver)
free_energy = FreeEnergyDistance(theta=0.2, solver=solver)

    See the Lineax documentation for the full list of available solvers and their options.

    JAXScape solvers¤

    JAXScape provides four optional high-performance solvers as extras:

    Solver Execution Typical use and limits
    CholmodSolver CPU host callback Direct factorization for fixed sparse systems; efficient reuse when factorization memory fits. GPU arrays cross the host-device boundary.
    PyAMGSolver CPU host callback AMG-preconditioned CG when factorization storage is too costly. Multiple right-hand sides are solved serially.
    AMJaxCGSolver CPU setup; JAX solve on CPU or GPU Reusable multigrid preconditioner for repeated solves, with fresh CG state when the operator changes. No per-solve host callback.
    CuDSSSolver NVIDIA GPU, through cuDSS and spineax Direct factorization inside jax.jit, with cost and accuracy independent of conductance contrast. Linux x86-64 and Python 3.12 or newer.

    Installation:

    uv add jaxscape --extra cholespy   # Cholesky solver
uv add jaxscape --extra pyamg      # PyAMG solver
uv add jaxscape --extra amjax      # Lineax CG + AMJax preconditioner
uv add jaxscape --extra cudss      # cuDSS direct solver (NVIDIA GPU, CUDA 13)

    CI/CD coverage

    The standard CI test suite exercises CholmodSolver, PyAMGSolver and AMJaxCGSolver. CI has no NVIDIA GPU: it runs the sparse direct solver logic on a dense solver, and the CuDSSSolver tests marked gpu need an NVIDIA GPU with spineax and cuDSS.

    Algebraic multigrid solver¤

    AMJaxCGSolver separates hierarchy construction from the actual iterative solve. This matters when you want the solve itself to remain JIT-compatible and differentiable.

    The amjax extra installs AMJax 0.0.3 or newer and PyAMG. JAXScape delegates multigrid construction and cycles to AMJax's MultilevelSolver, and iteration and convergence checks to Lineax CG. Hierarchy arrays retain the input matrix's dtype. For ill-conditioned graph Laplacians, enable JAX_ENABLE_X64=true and explicitly construct the matrix and right-hand sides in float64; enabling x64 alone does not promote existing float32 arrays. Single-level hierarchies (typically tiny graphs) fall back to ordinary CG because AMJax 0.0.3 requires at least two levels for a multigrid cycle.

    In algebraic multigrid, the preconditioner is built as a hierarchy of progressively coarser linear systems derived from the original sparse operator. This hierarchy consists of coarse operators together with prolongation and restriction maps between levels; one multigrid cycle smooths the error on the fine level, transfers the residual to coarser levels, approximately solves there, and interpolates the correction back to the fine level.

    For direct sparse solves against an unchanged matrix, initialize the full solver state once:

    import jax.numpy as jnp
import lineax as lx
from jax.experimental.sparse import BCOO
from jaxscape.solvers import AMJaxCGSolver, BCOOLinearOperator

A = BCOO.from_scipy_sparse(...)
b = jnp.ones(A.shape[0], dtype=A.data.dtype)

solver = AMJaxCGSolver(rtol=1e-6, atol=1e-6, max_steps=1_000)
state = solver.init(BCOOLinearOperator(A), {})
x = lx.linear_solve(BCOOLinearOperator(A), b, solver, state=state).value

    For a matrix with the same sparsity pattern and other values, reinit keeps the hierarchy and binds CG to the new matrix:

    operator = BCOOLinearOperator(A1)
state = solver.reinit(operator, {}, state)
x = lx.linear_solve(operator, b, solver, state=state).value

    Distances do this for you, as Reusing solver state describes.

    Reusing solver state¤

    Solver setup can cost far more than a solve, as a sparse analysis or a multigrid hierarchy does. ResistanceDistance and FreeEnergyDistance share one state lifecycle:

    • distance.init(graph) builds the state of graph. Some solvers read concrete sparse indices or run host code, so call it outside jax.jit.
    • distance.reinit(graph, state) returns the state of another graph with the same sparsity pattern, reusing what the solver can. It runs inside jax.jit.
    • Queries take that state, and all queries on a graph can share it. A query always solves the graph it is given: a state of another graph costs time and leaves the distances unchanged.

    A loop over conductances carries the state from one step to the next. The state carries no gradient, and has_aux=True passes it through the gradient transformation:

    import equinox as eqx
import jax
import jax.numpy as jnp
from jaxscape import GridGraph, ResistanceDistance
from jaxscape.solvers import AMJaxCGSolver


def landscape(log_conductance):
    return GridGraph(jnp.exp(log_conductance), fun=lambda x, y: (x + y) / 2)


sites = jnp.array([0, 45, 99])
true_log_conductance = jax.random.normal(jax.random.key(0), (10, 10))
target = ResistanceDistance()(landscape(true_log_conductance), nodes=sites)

distance = ResistanceDistance(
    solver=AMJaxCGSolver(rtol=1e-6, atol=1e-6, max_steps=1_000)
)
log_conductance = jnp.zeros((10, 10))
state = distance.init(landscape(log_conductance))


def loss(log_conductance, state):
    grid = landscape(log_conductance)
    state = distance.reinit(grid, state)
    predicted = distance.nodes_to_nodes_distance(grid, sites, state)
    return jnp.mean((predicted - target) ** 2), state


@eqx.filter_jit
def step(log_conductance, state):
    (value, state), gradient = eqx.filter_value_and_grad(loss, has_aux=True)(
        log_conductance, state
    )
    return log_conductance - 0.1 * gradient, value, state


for _ in range(10):
    log_conductance, value, state = step(log_conductance, state)

    What a state keeps from one graph to the next:

    Solver Kept by the state
    AMJaxCGSolver The multigrid hierarchy
    CuDSSSolver The sparse analysis, and the factorization while the values stay the same
    CholmodSolver Its last factorization, while the values stay the same
    PyAMGSolver, Lineax solvers Nothing: each query runs init, which only records the matrix

    Writing a sparse direct solver¤

    AbstractSparseDirectSolver turns the phases of a sparse factorization library into a Lineax solver for symmetric positive definite matrices, usable by every distance. It provides the state lifecycle, the CSR sparsity pattern, and the checks of each factorization and solve.

    import jax.numpy as jnp
from jaxscape.solvers import AbstractSparseDirectSolver


class MySolver(AbstractSparseDirectSolver):
    def factorize(self, pattern, values):
        return my_library.factorize(pattern.offsets, pattern.columns, values)

    def refactorize(self, factorization, pattern, values):  # Optional.
        return my_library.refactorize(factorization, values)

    def solve(self, factorization, vector):
        return my_library.solve(factorization, vector)

    def residual_tolerance(self, dtype):
        return 1e-4 if dtype == jnp.float64 else 1e-1

    The phases run inside jax.jit. Set residual_tolerance from the residuals the library leaves on valid matrices of your workload.

    A solver of another kind whose state outlives the matrix values subclasses AbstractReusableStateSolver and implements reinit.

    Solver reference¤

    jaxscape.solvers.cholmodsolver.CholmodSolver ¤

    A linear solver that uses CHOLMOD (via cholespy) to solve a sparse linear system. Uses direct Cholesky factorization for symmetric positive definite matrices. A state keeps its last factorization, which solves reuse while the matrix values stay the same.

    Example

    from jaxscape.solvers import CholmodSolver

solver = CholmodSolver()
distance = ResistanceDistance(solver=solver)
state = distance.init(grid)  # pre-factorizes the grounded Laplacian
dist = distance(grid, state=state)

    Warning

    cholespy must be installed to use this solver.

    Warning

    Float64 callback-backed solves require process-wide x64 support to be enabled before JAX work starts, e.g. via JAX_ENABLE_X64=1 or jax.config.update("jax_enable_x64", True). A thread-local with jax.enable_x64() block is not sufficient for host callback threads, and can surface as a callback dtype mismatch such as Expected: float64, Actual: float32.

    jaxscape.solvers.pyamgsolver.PyAMGSolver ¤

    A linear solver that uses PyAMG to solve a sparse linear system.

    Example

    from jaxscape.solvers import PyAMGSolver

solver = PyAMGSolver(rtol=1e-6, atol=1e-6, maxiter=100_000)
distance = ResistanceDistance(solver=solver)
dist = distance(grid)

# Custom AMG method
import pyamg
solver = PyAMGSolver(pyamg_method=pyamg.ruge_stuben_solver)

    Warning

    PyAMG must be installed to use this solver.

    jaxscape.solvers.amjaxcgsolver.AMJaxCGSolver ¤

    A Lineax CG solver with an AMJax algebraic multigrid preconditioner.

    The PyAMG hierarchy setup is performed once before entering Lineax's traced solve path. The resulting AMJax V-cycle is wrapped as a lineax.FunctionLinearOperator and supplied to lineax.CG through the preconditioner option.

    Example

    import lineax as lx
from jaxscape.solvers import AMJaxCGSolver, BCOOLinearOperator

solver = AMJaxCGSolver(rtol=1e-6, atol=1e-6, max_steps=1_000)
state = solver.init(BCOOLinearOperator(A), {})
x = lx.linear_solve(BCOOLinearOperator(A), b, solver, state=state).value

# Keep the hierarchy for a matrix of the same sparsity with other values.
state = solver.reinit(BCOOLinearOperator(A1), {}, state)
x = lx.linear_solve(BCOOLinearOperator(A1), b, solver, state=state).value

    Warning

    amjax and pyamg must be installed to use this solver.

    Reverse-mode gradients through solver calls require a symmetric AMJax preconditioner. This holds for the default matching pre/post Jacobi smoothers, but may not hold for custom non-symmetric smoother choices. Such configurations can still be valid for forward solves, but Lineax may need to transpose the preconditioner during autodiff.

    jaxscape.solvers.cudsssolver.CuDSSSolver ¤

    Sparse Cholesky solver running NVIDIA cuDSS on the GPU through spineax.

    Solves float32 and float64 systems. One query shares a factorization across its right-hand sides in one multi-RHS cuDSS solve, and it is not differentiated: gradients reuse the forward solutions or factorization. See AbstractSparseDirectSolver for the checks of each factorization and solve, which spineax does not report itself.

    Warning

    It needs an NVIDIA GPU of compute capability 7.5 or newer and CUDA-enabled JAX, and raises an error naming what is missing elsewhere. The cudss extra, pip install 'jaxscape[cudss]', installs spineax 0.0.5 and cuDSS below 1.0 for CUDA 13, on Linux x86-64 with Python 3.12 or newer. It brings JAX's CUDA 13 plugin, so leave out the cuda extra. For CUDA 12, build spineax from source as in these notes.

    Warning

    cuDSS allocates factorizations outside JAX's memory pool, so leave room with XLA_PYTHON_CLIENT_PREALLOCATE=false. spineax keeps the 8 most recently used factorizations in device memory; SPINEAX_FACTOR_CACHE sets that number.

    Note

    reinit uses up the factorization of the state it refactorizes, because cuDSS handles cannot be copied (spineax issue #27). A used-up or evicted state stays correct, and spineax repeats its costly analysis, so pass each new state to the next reinit. In float32, vertices cut off from the ground vertex can pass the solve check on grids of 300 x 300 cells or more; use float64 when conductances can be zero.

    jaxscape.solvers.sparsedirectsolver.AbstractSparseDirectSolver ¤

    Direct solver for sparse symmetric positive definite matrices.

    Subclass it with the phases of a sparse factorization library: factorize, solve, residual_tolerance and, when the library can reuse an analysis, refactorize. The base class provides the Lineax solver: it derives the CSR pattern once, refactorizes when the values change, and checks results.

    The checks assume nothing from the library. Each factorization solves A x = A 1, and fails when the backward error max|A 1 - A x| / (||A||_inf max|x|) is not finite or exceeds the square root of the machine epsilon. Each solve fails when its solution x of b is not finite or max|b - A x| exceeds residual_tolerance times max|b|. A failed solve returns NaN and reports lineax.RESULTS.singular, so it raises with throw=True and returns a failed result with throw=False. On GPUs, Lineax may only print the error, and the failed distances are then NaN.

    A refactorization that fails its check is retried on a fresh analysis, and the next reinit of a failed state analyses its values afresh, so a failure leaves later values exact. The checks cost one solve of one right-hand side and two sparse matrix-vector products per factorization, and one sparse matrix-vector product per right-hand side.

    Warning

    init reads concrete sparse indices, so create the state outside jax.jit. A state belongs to one sparsity pattern: for a GridGraph, the raster shape and contiguity, with any conductances. reinit raises an error for an operator with other sparse indices.

    jaxscape.solvers.operator.AbstractReusableStateSolver ¤

    Lineax solver whose state can serve another operator of the same sparsity.

    Subclass it when part of a state outlives the matrix values, such as a sparse analysis, a factorization or a multigrid hierarchy, and implement reinit. Distance queries call reinit on the state they receive before solving. Other Lineax solvers run init for each query, which suits iterative solvers, whose init only records the operator.

    reinit(operator: AbstractLinearOperator, options: dict[str, typing.Any], state: typing.Any) -> typing.Any ¤

    Return the state that solves operator, reusing what it can from state.

    It runs inside jax.jit. A query calls it on every state it receives, so it should do no expensive work when state already solves operator.

    Arguments:

    • operator: The operator to solve. It has the sparsity pattern of the operator state was built for, possibly different values, and no gradient.
    • options: Solver options, as passed to init.
    • state: A state returned by init or reinit.

    Returns:

    The state to solve operator with, with the structure of a state from init, so that a compiled loop can carry it.

    Advanced: BCOOLinearOperator¤

    JAXScape exposes a lineax-compatible linear operator that wraps JAX's native BCOO sparse matrix format. It lets compatible Lineax solvers operate on sparse matrices without converting to a dense representation, and is used internally by the four optional solvers above.

    jaxscape.solvers.operator.BCOOLinearOperator ¤

    lineax.MatrixLinearOperator wrapper for jax.experimental.sparse.BCOO matrices.
