    Linear solvers¤

    Computing resistance and free-energy distances, and their gradients, requires solving linear systems in a sparse symmetric positive definite matrix of the graph, which AbstractSolverDistance.system_matrix returns. For ResistanceDistance, this matrix is the graph Laplacian grounded at one vertex. For FreeEnergyDistance, with conductances \(a_{ij}\) and inverse temperature \(\theta\), it is the Laplacian of the edge weights \(a_{ij} e^{-\theta / a_{ij}}\) plus the positive diagonal \(\kappa_i = \sum_j a_{ij} (1 - e^{-\theta / a_{ij}})\). A linear solver, passed as the solver argument of the distance, solves these systems; with solver=None, the distances are computed with dense linear algebra instead. The solver sets the runtime, the memory and the accuracy of the distances.

    Choosing a solver¤

    The default solver of ResistanceDistance is GeometricMultigridCGSolver(): conjugate gradients (CG) preconditioned by geometric multigrid, in JAX on CPU and GPU, for the matrices of grid graphs such as those of GridGraph. On other graphs, the default solver raises an error; pass solver. FreeEnergyDistance uses dense linear algebra by default, solver=None.

    Distance and query GPU CPU
    Resistance distances among a few vertices: nodes_to_nodes_distance, few sources and targets, gradient-based fitting of conductances to observed distances, and SpielmanApproximation GeometricMultigridCGSolver, the default GeometricMultigridCGSolver, the default
    Resistance distances from one or all sources to every vertex: all_pairs_distance, and windowed analyses with ExactResistance solver=None for small graphs and tiles; GeometricMultigridCGSolver for larger ones solver=None for small graphs and tiles; CholmodSolver for larger ones
    Free-energy distances solver=None, the default, for small graphs; CuDSSSolver for larger ones solver=None for small graphs; CholmodSolver for larger ones
    Resistance or free-energy distances on graphs other than grid graphs solver=None for small graphs; CuDSSSolver for larger ones; AMJaxCGSolver when the factorization does not fit in memory solver=None for small graphs; CholmodSolver for larger ones; AMJaxCGSolver when the factorization does not fit in memory

    In float64, on GPUs of low float64 throughput, CuDSSSolver can compute resistance distances faster than GeometricMultigridCGSolver.

    Memory restricts the choice first. Dense linear algebra stores matrices of \(n^2\) entries for a graph of \(n\) vertices, and so fits small graphs only. GeometricMultigridCGSolver stores the matrix on its grid and a few arrays of \(n\) entries per right-hand side. Sparse direct solvers store a factorization of the matrix; when it does not fit in memory, use GeometricMultigridCGSolver on grid graphs and AMJaxCGSolver on other graphs.

    The entries of the inverse of the free-energy system matrix decay exponentially with path cost. Iterative solvers therefore need tolerances far below their defaults to resolve the distances between distant vertices, and in float32, the distances are accurate over a limited range of theta on a given landscape.

    With a solver, ResistanceDistance requires a connected graph: the grounded Laplacian of a disconnected graph is singular, and queries raise an error. A grid graph is disconnected when some of its pixels are joined to the others only by edges of zero conductance, such as the edges that the weight function fun of GridGraph gives between pixels of zero permeability. Windowed analyses raise permeability to a floor value, so that their graphs are connected.

    The tolerance at which a solver gives accurate distances depends on the query and on the floating-point precision. A solver can converge and still give inaccurate distances: check the distances of your queries, for example against solver=None on a small graph. The measurements behind this page are in issue #35.

    Lineax solvers¤

    Any Lineax solver of sparse symmetric positive definite operators can be passed as solver, such as conjugate gradients without preconditioner, lineax.CG:

    import lineax as lx
from jaxscape import FreeEnergyDistance, ResistanceDistance

solver = lx.CG(rtol=1e-6, atol=1e-6)
resistance = ResistanceDistance(solver=solver)
free_energy = FreeEnergyDistance(theta=0.2, solver=solver)

    The distance passes its system matrix to the solver as a BCOOLinearOperator. The Lineax documentation lists the available solvers and their options.

    JAXScape solvers¤

    jaxscape.solvers provides four solvers. GeometricMultigridCGSolver needs no optional dependency. Each of the three others needs one, installed with an extra of jaxscape:

    uv add jaxscape --extra cholespy   # CholmodSolver
uv add jaxscape --extra amjax      # AMJaxCGSolver
uv add jaxscape --extra cudss      # CuDSSSolver (NVIDIA GPU, CUDA 13)
    Solver Method Execution Graphs
    GeometricMultigridCGSolver Conjugate gradients preconditioned by geometric multigrid JAX, on CPU or GPU Grid graphs
    AMJaxCGSolver Conjugate gradients preconditioned by algebraic multigrid Preconditioner built on the CPU; solves in JAX, on CPU or GPU Any connected graph
    CholmodSolver Sparse Cholesky factorization CHOLMOD on the CPU, through a host callback Any connected graph
    CuDSSSolver Sparse Cholesky factorization NVIDIA cuDSS on the GPU, inside jax.jit Any connected graph

    A host callback runs Python code on the CPU from a compiled JAX program. Arrays on a GPU then travel to the CPU and back.

    Geometric multigrid¤

    GeometricMultigridCGSolver solves the matrices of grid graphs, such as the grounded Laplacian of a GridGraph with rook or queen contiguity, by conjugate gradients preconditioned by geometric multigrid. It is the default solver of ResistanceDistance. It runs in JAX on CPU and GPU, in float32 and float64, inside jax.jit, and needs no optional dependency.

    Theory: multigrid preconditioning

    The number of conjugate gradient iterations grows with the condition number of the matrix, which grows with the size of the grid and with the contrast of conductances. A preconditioner is an approximate inverse of the matrix, which the solver applies at each iteration, so that it reaches the tolerance in fewer iterations. In multigrid, the solver builds the preconditioner from a hierarchy of coarser grids: by relaxation on a grid, it lowers the components of the error that vary from pixel to pixel, and by corrections on the coarser grids, the components that vary smoothly, at a fraction of the cost. In geometric multigrid, the solver builds the coarser grids from the raster: each holds every other pixel along each axis. The cycle, the interpolation between grids and the solve on the coarsest grid are given in the API entry of GeometricMultigridCGSolver below.

    The preconditioner of its state is the grid, a raster shape and contiguity. init reads the grid from the sparse indices of the matrix; distance.init(graph) reads it from the shape and contiguity of a GridGraph, also inside jax.jit. reinit replaces the values of the matrix with those of another matrix of the same grid. Each solve builds the multigrid hierarchy of the matrix it solves, so that each tile of a windowed analysis is solved with the hierarchy of its own conductances.

    from jaxscape import ResistanceDistance, SpielmanApproximation
from jaxscape.solvers import GeometricMultigridCGSolver

exact = ResistanceDistance()  # GeometricMultigridCGSolver(rtol=1e-5)
approximate = ResistanceDistance(
    solver=GeometricMultigridCGSolver(rtol=3e-4),
    method=SpielmanApproximation(epsilon=0.15),
)

    rtol is the bound on the norm of the residual that conjugate gradients update at each iteration, relative to the norm of the right-hand side. With a larger rtol, the solves take fewer iterations. In float32, because of rounding, the residual b - A x of the solution x stops decreasing at some level; with an rtol below that level, the iterations continue without improving the solution. The resistances to pixels behind barriers converge last: with a large rtol, the gradient of the distances with respect to the permeability of these pixels loses accuracy first.

    In float32 on grid graphs, GeometricMultigridCGSolver gives the most accurate resistance distances of the JAXScape solvers. In float32, sparse direct solvers give inaccurate solutions around the ground vertex of large tiles (see the note on grounding of ResistanceDistance): use them in float64.

    jaxscape.solvers.geometricmultigridcgsolver.GeometricMultigridCGSolver ¤

    Conjugate gradients preconditioned by geometric multigrid, for grid graphs.

    Solves the symmetric positive definite matrices whose sparsity pattern is a grid stencil, such as the grounded Laplacians of a GridGraph with rook or queen contiguity, in which ResistanceDistance solves linear systems. It is the default solver of ResistanceDistance. It runs in JAX, on any device, in float32 and float64, and needs no optional dependency. Its preconditioner is the grid, which init reads from concrete sparse indices. Each solve builds the multigrid hierarchy of the current values on it, at a small fraction of the cost of the solve. A compiled program then holds one hierarchy for each place where it solves, whatever the states it reinitializes.

    Each V-cycle has one iteration of damped Jacobi relaxation before and after the coarse correction. The coarse grids hold every other point along each axis. The values at the other points are interpolated from the matrix coefficients, as in black-box multigrid (Dendy, 1982), so that convergence stays fast across jumps of conductance. The matrices of the coarse grids are the Galerkin products of the interpolation. The first grid of at most 1024 points is solved with a Cholesky factorization.

    With a larger rtol, the solves take fewer iterations, at the cost of the accuracy of the resistances to pixels behind barriers, which converge last. On large grids in float32, the solutions of this solver stay accurate around the ground vertex of ResistanceDistance, where those of sparse direct solvers lose accuracy. It factorizes only the matrix of the coarsest grid, which suits conductances that change at every step, as in optimization loops. In float64, sparse direct solvers can be faster.

    Attributes:

    • rtol: Largest Euclidean norm of the residual, relative to that of the right-hand side (see AbstractSparseIterativeSolver).
    • max_steps: Largest number of iterations.

    Warning

    A state belongs to one grid: a raster shape and contiguity, with any conductances. The matrix must be positive definite: a grounded Laplacian of a connected graph. The solves of a singular matrix fail with lineax.RESULTS.singular when their solution is not finite, and with lineax.RESULTS.max_steps_reached otherwise.

    Algebraic multigrid¤

    In algebraic multigrid, the coarser levels are built from the entries of the matrix, without a grid, so that the matrix of any graph can be preconditioned. AMJaxCGSolver solves by conjugate gradients preconditioned by an algebraic multigrid hierarchy, built by smoothed aggregation by default. It suits graphs other than grid graphs whose sparse Cholesky factorization does not fit in memory.

    AMJaxCGSolver builds the hierarchy once, in init, on the CPU. It solves by conjugate gradients, preconditioned by V-cycles of the hierarchy, in JAX on CPU or GPU, inside jax.jit and jax.grad. reinit keeps the prolongation and restriction operators of the hierarchy, and each solve computes the matrices of its coarser levels from the current values, as Galerkin products with these operators. The state also holds, for each level but the coarsest, the map from the values of the level to those of the next: sparse matrices several times the size of the hierarchy. The hierarchy has the dtype of the matrix. For ill-conditioned graph Laplacians, enable 64-bit floats with JAX_ENABLE_X64=true and build the matrix and the right-hand sides in float64: enabling 64-bit floats does not convert existing float32 arrays. A matrix whose hierarchy has a single level, as that of a small graph, is solved by conjugate gradients without preconditioner.

    jaxscape.solvers.amjaxcgsolver.AMJaxCGSolver ¤

    Conjugate gradients preconditioned by algebraic multigrid, with AMJax.

    Its preconditioner is a multigrid hierarchy, which init builds once on the host with PyAMG, from the values it is given, and converts to an AMJax hierarchy. Each solve applies one V-cycle of that hierarchy per iteration, in JAX, inside jax.jit and jax.grad. reinit keeps the prolongation and restriction operators of the hierarchy, and each solve computes the matrices of its coarser levels from the current values, as Galerkin products with these operators. The state also holds, for each level but the coarsest, the map from the values of the level to those of the next: sparse matrices several times the size of the hierarchy. The hierarchy keeps the dtype of the matrix. With a hierarchy of a single level, as that of a tiny graph, conjugate gradients run without a preconditioner.

    Example

    from jaxscape import ResistanceDistance
from jaxscape.solvers import AMJaxCGSolver

distance = ResistanceDistance(solver=AMJaxCGSolver(rtol=1e-6))
state = distance.init(grid)  # builds the hierarchy
dist = distance(grid, state=state)

    Attributes:

    • rtol: Largest Euclidean norm of the residual, relative to that of the right-hand side (see AbstractSparseIterativeSolver).
    • max_steps: Largest number of iterations.
    • pyamg_method: The PyAMG function that builds the hierarchy from a SciPy CSR matrix. Defaults to pyamg.smoothed_aggregation_solver.
    • pyamg_kwargs: Keyword arguments of pyamg_method.
    • presmoother, postsmoother: AMJax smoothers, as (name, kwargs), both required. Default to one iteration of Jacobi of weight 2/3. A Jacobi smoother with withrho=True keeps the weight that init computes from the spectral radius of its level.
    • coarse_solver: AMJax solver of the coarsest level. The coarse solvers "pinv", "lu" and "qr" keep the factorization of the coarsest matrix of init.
    • coarse_solver_kwargs: Keyword arguments of coarse_solver.

    Warning

    amjax and pyamg must be installed to use this solver, with uv add jaxscape --extra amjax. Conjugate gradients need a symmetric positive definite V-cycle. With Jacobi smoothers of weight ω and the "jacobi" coarse solver, the V-cycle is one when ω times the spectral radius of D⁻¹A, for the matrix A of a level and its diagonal D, is below 2 on every level; on the coarsest level, ω is the weight of the coarse solver, 1 by default. With values other than those of init, a coarser level can have a spectral radius above 2, and the default weight of the smoothers, 2/3, admits spectral radii up to 3 on the levels they smooth.

    Sparse direct solvers¤

    A sparse Cholesky factorization of the matrix is a product \(L L^\top\), with \(L\) sparse and lower triangular, after a reordering of its rows and columns that limits the number of entries of \(L\). Each solve then takes two triangular solves. The factorization costs far more than a solve, and many right-hand sides share it. Its cost depends on the sparsity pattern of the matrix only, and is the same whatever the contrast of conductances. CholmodSolver and CuDSSSolver solve the matrix of any connected graph. In float32, their solutions on large grids are inaccurate around the ground vertex of ResistanceDistance.

    CholmodSolver factorizes with CHOLMOD, through cholespy, on the CPU, through a host callback. Solves reuse the last factorization while the values of the matrix stay the same.

    CuDSSSolver factorizes with NVIDIA cuDSS, through spineax, on the GPU, inside jax.jit. Its state keeps the analysis of the sparsity pattern: the ordering of the rows and columns and the structure of \(L\). A matrix with new values is factorized on this analysis. It needs an NVIDIA GPU and Linux x86-64.

    jaxscape.solvers.cholmodsolver.CholmodSolver ¤

    Sparse Cholesky factorization with CHOLMOD, through cholespy, on the CPU.

    Solves symmetric positive definite matrices through a host callback. Solves reuse the last factorization while the values of the matrix stay the same, and factorize the matrix again when they change. The solver keeps one factorization, so under jax.vmap over the values of the matrix, each solve factorizes every distinct matrix of the batch.

    Attributes:

    • factorize_in_init: Whether init, called outside jax.jit, factorizes the matrix. Otherwise, or when init runs inside jax.jit, the first solve factorizes it. Defaults to True.

    Example

    from jaxscape.solvers import CholmodSolver

solver = CholmodSolver()
distance = ResistanceDistance(solver=solver)
state = distance.init(grid)  # factorizes the grounded Laplacian
dist = distance(grid, state=state)

    Warning

    cholespy must be installed to use this solver, with uv add jaxscape --extra cholespy.

    Warning

    Float64 solves run through a host callback, and require 64-bit floats enabled for the whole process before JAX computes anything, with JAX_ENABLE_X64=1 or jax.config.update("jax_enable_x64", True). A with jax.enable_x64() block enables them in its own thread only, and the host callback then fails with a dtype mismatch such as Expected: float64, Actual: float32.

    jaxscape.solvers.cudsssolver.CuDSSSolver ¤

    Sparse Cholesky solver running NVIDIA cuDSS on the GPU through spineax.

    Solves float32 and float64 systems. A query solves all its right-hand sides in one call of cuDSS, with one factorization. JAX does not differentiate through the solves: the gradients are computed from the solutions or the factorization of the query. See AbstractSparseDirectSolver for the checks of each factorization and solve.

    Warning

    It needs an NVIDIA GPU and CUDA-enabled JAX, and raises an error naming what is missing elsewhere. The cudss extra, uv add jaxscape --extra cudss, installs spineax and cuDSS for CUDA 13, on Linux x86-64. It brings JAX's CUDA 13 plugin, so leave out the cuda extra. For CUDA 12, build spineax from source as in these notes.

    Warning

    The factorizations are held outside JAX's memory pool, so leave room with XLA_PYTHON_CLIENT_PREALLOCATE=false. SPINEAX_FACTOR_CACHE sets the number of factorizations that spineax keeps in device memory.

    Note

    reinit consumes the factorization of the state it refactorizes. A used-up state, or one evicted from spineax's cache, still gives correct solutions, but each solve with it repeats the analysis, which is costly: pass each new state to the next reinit. In float32, on large grids, a matrix with vertices cut off from the ground vertex can pass the solve check; use float64 when conductances can be zero.

    Note

    In float32, solutions on large grids are inaccurate around the ground vertex of ResistanceDistance. For permeability sensitivity on large tiles, use float64, or GeometricMultigridCGSolver in float32.

    Reusing solver state¤

    Building the state of a solver, as a sparse factorization or a multigrid hierarchy, can cost far more than a solve. ResistanceDistance and FreeEnergyDistance share one state lifecycle:

    • distance.init(graph) builds the state for the system matrix of graph. JAXScape's sparse solvers, except CholmodSolver, read concrete sparse indices, and AMJaxCGSolver runs code on the CPU, so call it outside jax.jit. ResistanceDistance also builds the state of a GridGraph inside jax.jit, from the shape and contiguity of the graph. The compiled program then holds the arrays of the state as constants: on large grids, it compiles faster with the state passed as an argument.
    • distance.reinit(graph, state) returns the state for another graph of the same sparsity pattern, and keeps what the solver can reuse. It runs inside jax.jit.
    • Queries take the state as state, and the queries on one graph can share it. A query always solves the system matrix of the graph it receives: an outdated state can make the query slower, and leaves its distances unchanged.

    An optimization loop over conductances passes the state from one step to the next, whatever the solver. distance.init returns a state with Lineax's and JAXScape's solvers, and None only with solver=None. For a solver that keeps nothing from one matrix to the next, such as lineax.CG, reinit ignores the state and returns init(graph). The state has no gradient: with has_aux=True, the differentiated function returns it alongside the loss.

    import equinox as eqx
import jax
import jax.numpy as jnp
from jaxscape import GridGraph, ResistanceDistance


def landscape(log_conductance):
    return GridGraph(jnp.exp(log_conductance), fun=lambda x, y: (x + y) / 2)


sites = jnp.array([0, 45, 99])
true_log_conductance = jax.random.normal(jax.random.key(0), (10, 10))
target = ResistanceDistance()(landscape(true_log_conductance), nodes=sites)

distance = ResistanceDistance()  # GeometricMultigridCGSolver
log_conductance = jnp.zeros((10, 10))
state = distance.init(landscape(log_conductance))


def loss(log_conductance, state):
    grid = landscape(log_conductance)
    state = distance.reinit(grid, state)
    predicted = distance.nodes_to_nodes_distance(grid, sites, state)
    return jnp.mean((predicted - target) ** 2), state


@eqx.filter_jit
def step(log_conductance, state):
    (value, state), gradient = eqx.filter_value_and_grad(loss, has_aux=True)(
        log_conductance, state
    )
    return log_conductance - 0.1 * gradient, value, state


for _ in range(10):
    log_conductance, value, state = step(log_conductance, state)

    What the state of each solver keeps from one graph to the next:

    Solver Kept by the state
    GeometricMultigridCGSolver Its preconditioner, the grid; each solve builds the multigrid hierarchy of the new values
    AMJaxCGSolver Its preconditioner, the prolongation and restriction operators of the algebraic multigrid hierarchy of init; each solve computes the matrices of the coarser levels from the new values
    CuDSSSolver The analysis, and the factorization while the values stay the same
    CholmodSolver The last factorization, while the values stay the same
    Lineax's iterative solvers, such as lineax.CG Nothing: each query runs init

    The graphs of one raster shape and contiguity can also share a GridTopology, built once outside jax.jit. It holds their edges, so that each GridGraph(surface, fun=fun, topology=topology) computes its edge weights only.

    Windowed analyses build their own states and pass them from tile to tile; see WindowedAnalysis.

    Extending the solvers¤

    BCOOLinearOperator presents a sparse matrix to Lineax. AbstractSparseSolver is the parent of JAXScape's sparse solvers of symmetric positive definite matrices. Its state holds the compressed sparse row (CSR) sparsity pattern of the matrix, read once from concrete sparse indices, the values, which reinit replaces inside jax.jit, and a factorization or a preconditioner. It scales right-hand sides, checks the sparse indices of each new matrix, and reports failed solves. A new solver subclasses one of its two families, with a final class. The methods that it implements take the sparsity pattern as a CSRPattern: its arrays offsets and columns give the columns of each row, and its properties n, nnz and rows the number of rows, the number of CSR values and the row of each CSR value.

    AbstractSparseDirectSolver turns the phases of a sparse factorization library into a solver, and checks each factorization and solve; CuDSSSolver subclasses it:

    from typing import final

import jax.numpy as jnp
from jaxscape.solvers import AbstractSparseDirectSolver


@final
class MySolver(AbstractSparseDirectSolver):
    def factorize(self, pattern, values):
        return my_library.factorize(pattern.offsets, pattern.columns, values)

    def refactorize(self, factorization, pattern, values):  # Optional.
        return my_library.refactorize(factorization, values)

    def solve(self, factorization, vector):
        return my_library.solve(factorization, vector)

    def residual_tolerance(self, dtype):
        return 1e-4 if dtype == jnp.float64 else 1e-1

    The phases run inside jax.jit. Set residual_tolerance from the residuals the library leaves on valid matrices of your workload.

    AbstractSparseIterativeSolver runs conjugate gradients with a preconditioner; GeometricMultigridCGSolver and AMJaxCGSolver subclass it. preconditioner builds what the state keeps across values, in init, and precondition returns the preconditioner of the current values at each solve, as a function of residuals. matvec returns the product of the current matrix with vectors, and vector_shape the shape in which both take vectors: csr_matvec multiplies vectors of shape (n,) with the CSR values, and GeometricMultigridCGSolver multiplies rasters with its stencil. Jacobi preconditioning keeps nothing:

    from typing import final

import jax.numpy as jnp
from jaxscape.solvers import AbstractSparseIterativeSolver, csr_matvec


@final
class JacobiCGSolver(AbstractSparseIterativeSolver):
    rtol: float = 1e-5
    max_steps: int = 1_000

    def preconditioner(self, pattern, values):
        return None

    def precondition(self, preconditioner, pattern, values):
        on_diagonal = jnp.where(pattern.rows == pattern.columns, values, 0)
        diagonal = jnp.zeros(pattern.n, values.dtype).at[pattern.rows].add(on_diagonal)
        return lambda residuals: residuals / diagonal[:, None]

    def matvec(self, preconditioner, pattern, values):
        return csr_matvec(pattern, values)

    def vector_shape(self, preconditioner, pattern):
        return (pattern.n,)

    jaxscape.solvers.operator.BCOOLinearOperator ¤

    Lineax linear operator of a jax.experimental.sparse.BCOO matrix.

    Its products with vectors are computed with the sparse matrix, so that Lineax solvers that only multiply by the operator, such as lineax.CG, never form a dense matrix. Every BCOOLinearOperator is registered with Lineax as positive semidefinite, whatever its tags, so that lineax.CG accepts it: pass only symmetric positive semidefinite matrices to such solvers.

    jaxscape.solvers.sparsesolver.CSRPattern ¤

    Compressed sparse row pattern of a BCOO matrix.

    Duplicate entries of the BCOO matrix share one CSR value, and its padding entries, whose indices are out of bounds, are left out.

    Attributes:

    • offsets: Start of each row in columns, with shape (n + 1,).
    • columns: Column of each CSR value, sorted within each row, with shape (nnz,).
    • value_map: For each stored entry of the BCOO matrix, the index of its CSR value, or nnz for padding entries.
    • max_row_length: Number of CSR values of the longest row. It is static: states whose longest rows differ compile separately.
    • n: Number of rows, and of columns, of the matrix.
    • nnz: Number of CSR values.
    • rows: Row of each CSR value, with shape (nnz,), computed from offsets at each access.

    jaxscape.solvers.sparsesolver.AbstractSparseSolver ¤

    Lineax solver of sparse symmetric positive definite matrices, with a state for one sparsity pattern.

    Subclass AbstractSparseDirectSolver with the phases of a sparse factorization library, or AbstractSparseIterativeSolver with a preconditioner. This class provides what they share. init reads the CSR pattern of the matrix from concrete sparse indices, and reinit replaces its values inside jax.jit, after checking that the sparse indices are those of the pattern. The state holds the pattern, the values, and the factorization or preconditioner of the solver.

    Each solve scales the right-hand side exactly, by a power of two, to a largest magnitude in [0.5, 1), so that its solution keeps the precision of the dtype: float32 right-hand sides of about 1e-37 had subnormal solutions. Right-hand sides below the smallest normal number solve to 0. A failed solve returns NaN and reports its failure through lineax.RESULTS, so it raises with throw=True and returns a failed result with throw=False. On GPUs, Lineax may only print the error, and the failed distances are then NaN.

    The matrix is symmetric: the state of a solver is also that of the transposed matrix.

    Warning

    init reads concrete sparse indices: distance.init(graph) builds the state of a GridGraph from its shape and contiguity, also inside jax.jit, and that of another graph outside jax.jit. A state belongs to one sparsity pattern: for a GridGraph, the raster shape and contiguity, with any conductances. reinit raises an error for an operator with other sparse indices.

    Arguments:

    • options: Unused.

    jaxscape.solvers.sparsedirectsolver.AbstractSparseDirectSolver ¤

    Direct solver for sparse symmetric positive definite matrices.

    Subclass it with the phases of a sparse factorization library: factorize, solve, residual_tolerance and, when the library can reuse an analysis, refactorize. The base class provides the Lineax solver, as AbstractSparseSolver describes: it factorizes the matrix again when its values change, and checks the results.

    reinit returns its state itself when the state passed its check and the values are those it factorizes, up to the rounding of assembling the matrix. Otherwise it refactorizes the state, whose factorization may no longer be valid afterwards, and analyses the values afresh when the state failed its check or when the refactorization fails its own.

    The checks assume nothing from the library. Each factorization solves A x = A 1, and fails when the backward error max|A 1 - A x| / (||A||_inf max|x|) is not finite or exceeds the square root of the machine epsilon. Each solve fails when its solution x of the scaled right-hand side b is not finite or max|b - A x| exceeds residual_tolerance times max|b|, and reports lineax.RESULTS.singular.

    A refactorization that fails its check is retried on a fresh analysis, and the next reinit of a failed state analyses its values afresh, so a failure leaves later values exact. The checks cost one solve of one right-hand side and two sparse matrix-vector products per factorization, and one sparse matrix-vector product per right-hand side.

    jaxscape.solvers.sparseiterativesolver.AbstractSparseIterativeSolver ¤

    Conjugate gradients on sparse symmetric positive definite matrices, with a preconditioner.

    Subclass it with preconditioner, which init builds once, precondition, which applies it to the current values at each solve, matvec, the product of the current matrix with vectors, and vector_shape, the shape of those vectors. csr_matvec gives the product of the CSR values, with vectors of shape (n,). The base class provides the Lineax solver, as AbstractSparseSolver describes: reinit keeps the preconditioner and replaces the values. Values other than those the preconditioner was built from change the number of iterations, and a solve that then exceeds max_steps fails.

    A batch of right-hand sides, as jax.vmap makes, runs as one solve with the right-hand sides contiguous in memory, until all have converged. A solve that has not converged after max_steps iterations fails with lineax.RESULTS.max_steps_reached, and one whose solution is not finite, as those of singular matrices can be, with lineax.RESULTS.singular.

    Attributes:

    • rtol: Largest Euclidean norm, relative to that of the right-hand side, of the residual that conjugate gradients update at each iteration. In exact arithmetic it equals the residual b - A x of the solution x. In float32, rounding stops the decrease of b - A x, so that solves can converge with a residual b - A x above rtol.
    • max_steps: Largest number of iterations.
